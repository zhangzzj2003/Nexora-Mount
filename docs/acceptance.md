# 双平台验收

构建通过、桌面自动化、本机临时服务器、真实 NAS 与双电脑 AI 是不同层次的证据，应分别记录日期、系统版本、NAS 型号/固件和协议设置。

## 自动化

- `pnpm typecheck`：TypeScript/Vue 接口一致性。
- `pnpm test`：地址与子路径、配置事务、凭证处理、重复操作、网络/认证错误、超时核对、占用卸载、诊断脱敏；macOS 额外验证真实原生挂载枚举。
- `pnpm test:e2e`：真正启动 Electron，新增两种连接、编辑、配置落盘、诊断和渲染隔离；使用 .invalid 域名，不访问真实 NAS。
- `NEXORA_NATIVE_E2E=1 pnpm test:e2e`：macOS 临时本机 Apache WebDAV 的挂载、读写、中文文件名、重命名、删除、刷新和卸载。该测试不代替 NAS 与 SMB 验收。

## 真实 NAS 测试

始终使用可删除的测试目录，开始前备份重要项目。分别填写 SMB/WebDAV 服务地址及测试账号，通过应用完成以下检查：

| 场景 | 预期 |
| --- | --- |
| 添加、测试、连接、打开、卸载 | 显示与系统一致的位置；端口测试与账号验证区分 |
| 重启应用 | 识别已有挂载，不创建重复卷 |
| 指定 Windows 盘符被占用 | 提示冲突，不替换其他磁盘 |
| 中文、空格、特殊字符 | 创建、修改、重命名和删除后远端内容一致 |
| WebDAV 反向代理子路径 | 实际挂载指定子目录 |
| HTTPS 无效/自签证书 | 不绕过校验，配置系统信任后重新连接 |
| 错误密码、账号权限不足 | 可读错误信息，不无限重试认证 |
| 只读账号、缺少 LOCK | 系统限制明确；不将无法写入报告为成功 |
| 超过 Windows 当前单文件限制 | 提示限制，核对系统错误行为 |
| 断网 60 秒、网络恢复 | 状态更新，验证可访问性；不能恢复时提示手动重连 |
| 睡眠唤醒、NAS 重启、密码更改 | 按错误类别恢复或要求用户处理 |
| 文件占用后卸载 | 保留系统错误，不强制卸载；关闭占用后可重试 |
| 写入期间断网 | 以编辑器和系统反馈为准，核对服务器文件与备份，不能仅凭连接灯判断写入成功 |

## 两台电脑与 AI

1. 两端挂载 NAS 同一个测试项目，记录操作系统、AI 工具与编辑器版本。
2. A 修改并保存；在 NAS 检查内容，B 重新读取并确认内容。
3. B 修改并保存；A 确认刷新与重新读取的结果。
4. 分别测试不同文件并行修改、同一文件不同位置修改及同一位置冲突。
5. 检查工具的外部变更通知、搜索结果、终端工作目录、Git 状态与构建结果。
6. 两端避免同时修改共享的 Git 索引或执行切分支、重置、依赖安装等项目级操作。开发依赖与产物可能依赖平台，Windows/macOS 共用 node_modules、虚拟环境等需要单独安排。

验收目标是直接使用同一份文件及明确呈现访问失败。自动合并、任务隔离与跨平台依赖环境统一不属于本版承诺。

## 发布

- 在各目标系统安装、启动、托盘退出并重新运行，检查配置仍在。
- 验证原生 Koffi 文件已解包并匹配架构。
- Intel Mac、Windows 真机需单独验收，不能由 Apple Silicon 构建结果推断通过。
- 正式发布核对签名、公证和安装引导，并附版本、SHA-256、已知限制及第三方许可。
